# Set up an ESPHome Bluetooth proxy

A proxy places a Bluetooth radio near the vehicle and forwards communication over
Wi-Fi or Ethernet. Decoding and schedules run in Home Assistant. This integration
can use a standard ESPHome proxy without installing BM-specific ESP32 code.

## Choose and place the hardware

Use a BLE-capable board supported by ESPHome Bluetooth proxy active connections.
The examples here target a generic **ESP32-WROOM development board** (`esp32dev`)
with ESP-IDF. Change the board configuration for different hardware. An ESP32-S2
does not provide Bluetooth and is unsuitable.

Start close to the vehicle, then test from the intended permanent location. Raise
the proxy off the floor, clear of metal surfaces, and away from sources of radio
interference. A battery monitor under a metal hood can be much harder to reach
than a Bluetooth device in the open. Check several Update now reads when choosing
the final position; detecting an advertisement alone does not prove a reliable
two-way connection.

For external antennas, look for a development board using an **ESP32-WROOM-32UE**
module and a matching 2.4 GHz antenna. Antenna connector types and antenna-selection
hardware vary by board. Follow the board maker's instructions; this YAML does not
configure a board-specific antenna switch.

If Ethernet is available, an **Olimex ESP32-POE-ISO-EA** is a supported option with an
external antenna and PoE. Use that board's ESPHome configuration instead of the
generic Wi-Fi example. Ethernet avoids sharing airtime between Wi-Fi and Bluetooth.
See [ESPHome's reception guidance](https://esphome.io/components/bluetooth_proxy/#improving-reception-performance)
and [HA's remote adapter recommendations](https://www.home-assistant.io/integrations/bluetooth/#remote-adapters-bluetooth-proxies).

## 1. Flash a proxy

The quickest route is the official
[ESPHome ready-made Bluetooth proxy installer](https://esphome.io/projects/?type=bluetooth).
Select firmware matching your board, flash it over USB, and configure its network.

To manage the YAML yourself in **ESPHome Device Builder**:

1. Copy [`battery-proxy.yaml`](../esphome/battery-proxy.yaml) into your ESPHome
   configuration directory. Its default device name is `battery-proxy-garage`.
2. Check the `esp32` board settings against your hardware and choose a unique name.
3. Add the entries from [`secrets.yaml.example`](../esphome/secrets.yaml.example)
   to ESPHome's `secrets.yaml`, filling in your Wi-Fi details and an API key.
4. Generate an API key with `openssl rand -base64 32`, or use a key generated by
   ESPHome. This is the key HA will request when adding the proxy.
5. Install the firmware over USB for the first flash. Subsequent updates can use OTA.

The supplied YAML requires **ESPHome 2026.10 or newer** for encrypted OTA, which
reuses the API encryption key. The API key is a device credential, not a BM6/BM7
decryption key. Keep `secrets.yaml` private.

The relevant Bluetooth settings are:

```yaml
esp32_ble_tracker:
  scan_parameters:
    active: false

bluetooth_proxy:
  active: true
```

These settings control different things:

- `esp32_ble_tracker.scan_parameters.active: false` listens passively instead of
  requesting additional scan responses from nearby devices.
- `bluetooth_proxy.active: true` enables the GATT connections needed to command and
  read a BM6/BM7. Keep this enabled even when using passive scanning.

## 2. Register it with Home Assistant

**Being online in ESPHome Device Builder is not sufficient.** Home Assistant must
connect to the device's native API before it can use the Bluetooth proxy.

1. Open **Settings → Devices & services** and look for a discovery card for the
   ESP32. Select **Add** and complete setup.
2. If no card appears, choose **Add integration → ESPHome**.
3. Enter the device's IP address or hostname, such as `battery-proxy-garage.local`.
   The default API port is **6053**.
4. Supply its API encryption key if prompted.
5. Confirm the device is connected. You can also inspect adapters and
   advertisements under **Settings → Connectivity → Bluetooth** in current HA.

For details, see the official [ESPHome integration guide](https://www.home-assistant.io/integrations/esphome/).

## 3. Discover the monitor, then use passive scanning

Some monitors only reveal their name in a scan response. An initial passive scan
may therefore receive the monitor's address without identifying it as BM6/BM7.
The integration's discovery menu only lists recognized names: `BM6`, `BM7`, and
`BM300 Pro`.

1. Keep the proxy close to the monitor and close any phone app holding a connection.
2. Open the proxy's **Configure** screen in the HA **ESPHome integration**.
3. Temporarily choose **Active** Bluetooth scanning, submit, and allow about
   30 seconds for names to appear. Reopen the BM6/BM7 discovery menu afterward.
4. Add the monitor with a vehicle name and the preferred polling interval.
5. Return the proxy's scanning mode to **Passive** in HA.
6. Press the monitor's **Update now** button once. Verify that **Last successful
   reading** advances and **Poll status** is OK.

Active scanning requests scan responses; it does not perform the integration's
encrypted battery-reading command. It still causes additional radio activity, so
the temporary discovery setting should not be left on if conserving battery power
is the priority. HA's saved scanner mode can override the device YAML; after
registration, change the running mode in HA.

If you already know the monitor's MAC address, you can add it manually instead.
A replacement proxy may receive an unnamed advertisement and still read an
already-configured monitor by its MAC address.

## 4. Cover another area

Flash another ESP32 with a different name and add it to HA in the same way. The
example [`battery-proxy-other-area.yaml`](../esphome/battery-proxy-other-area.yaml)
includes the first YAML file as a local package, overriding its name. Copy both
files into the same ESPHome directory before using the second example. The shared
example uses one API key for simplicity; independent devices may use different keys.

No monitor entry needs a proxy address. HA automatically selects a route using its
registered scanners. To replace hardware, verify the new proxy first and then
remove the old ESPHome device while retaining the battery-monitor entries.
